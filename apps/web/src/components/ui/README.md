# UI primitives

The components in this folder come from the [shadcn/ui](https://ui.shadcn.com) registry
(style `new-york`, Tailwind v4), generated by the shadcn CLI from `apps/web/components.json`.
Feature code builds on them instead of hand-written lookalikes.

shadcn/ui is MIT licensed (Copyright (c) 2023 shadcn). The license text is in
[`licenses/shadcn-ui-LICENSE`](../../../../../licenses/shadcn-ui-LICENSE) at the root of
this repository and the attribution is in `THIRD_PARTY_NOTICES.md`; keep both when
you copy a component.

## Adding a component

```sh
cd apps/web
pnpm dlx shadcn@latest add <component>
pnpm exec biome check --write src/components/ui
```

`biome check --write` formats, sorts the imports and applies the safe lint fixes
(`import type`), which is what the registry output needs to pass `pnpm lint`;
`biome format` alone leaves the imports unsorted.

**Discard any change the CLI makes to `src/index.css`.** Some registry items carry
CSS variables and the CLI merges them into the stylesheet named in `components.json`
(`sidebar`, for example, adds Tailwind v3 HSL variables such as
`--sidebar-background` to `@layer base`). The tokens in `src/index.css` are
maintained by hand in OKLCH and checked by `tokens.test.ts`; a new component uses
the existing tokens, and a genuinely new token is added by hand, in light and dark.
Most components (`kbd` or `empty`, for instance) add without touching the file.

Without `--overwrite` the CLI skips files that already exist. **Never pass
`--overwrite` for the files listed below**: they carry Restow changes that a
regeneration would silently drop. Registry hooks land in `hooks/`.

## Where Restow differs from the registry

| File | Change | Why |
| --- | --- | --- |
| `button.tsx` | `loading` prop; defaults to `type="button"`; exports `ButtonProps` | a busy button shows one spinner in place of its leading icon; buttons never submit a form by accident |
| `badge.tsx` | tones `success`, `warning`, `destructive`, `info`, `muted`; exports `BadgeProps`; no `overflow-hidden` and no `whitespace-nowrap`; radius of half the one-line height instead of `rounded-full` | status badges use the text-safe `--<tone>-text` tokens on a tint; a long status label wraps instead of being clipped, so failure information is never cut off, and a wrapped badge stays a rounded rectangle instead of a blob |
| `alert.tsx` | tones `info`, `success`, `warning`; `role="alert"` only for `destructive` and `warning`; no title line clamp | only problems interrupt a screen reader; messages are never truncated |
| `checkbox.tsx` | indeterminate state (dash) | "select all" over a partial selection |
| `dialog.tsx` | translated close labels; `w-full max-w-lg`; the content sits inside its overlay, which spans the viewport from the top and is at most one viewport high (`100dvh`, `100vh` fallback), and centres it with auto margins (no `top: 50%` plus a -50% translate); the content is capped at that height and scrolls; `DialogHeader` (unless `sr-only`) and `DialogFooter` are sticky; exports the layout classes (`DIALOG_LAYER`, `DIALOG_BOX`, `STICKY_HEADER`, `STICKY_FOOTER`) | a caller's `max-w-*` widens the dialog on every breakpoint; a tall dialog never leaves the screen, the wheel scrolls it, its title and buttons stay visible |
| `alert-dialog.tsx` | placed, capped and scrolling like `dialog.tsx`, sticky header and footer | the same guarantees for confirmations |
| `sheet.tsx` | translated close label; `hideClose`; 200 ms open and close (registry: 500 ms and 300 ms); at most one viewport high (`100dvh`, `100vh` fallback) and scrolling inside | kept for existing callers; the same motion as dialog, alert dialog and sidebar; the end of a long sheet stays reachable |
| `select.tsx` | `SelectContent` defaults to `position="popper"`, `align="start"`, at most `min(available height, 24rem)` high, at least as wide as the trigger and as wide as the longest item (within the viewport); the trigger value wraps instead of `line-clamp-1`, the trigger keeps its 36 px (32 px small) minimum height | the registry's `item-aligned` list laid itself over the trigger and grew past the viewport while scrolling; a value is never cut off |
| `sonner.tsx` | app `ThemeProvider` instead of next-themes; translated labels; re-exports `toast` | one theme source; no English defaults |
| `sidebar.tsx` | state in local storage instead of a cookie; translated labels | the app renders on the client and never reads the cookie |
| `command.tsx` | `CommandDialog` requires `title` and `description`; header inside the content; `CommandList` has `overscroll-behavior: contain` | screen readers announce the palette in the app language; scrolling past the end of a list in a popover does not scroll the page (and the popover with it) away |
| `breadcrumb.tsx`, `pagination.tsx` | translated landmark and button labels | no English defaults |
| `calendar.tsx` | locale follows the app language | German month and weekday names in the German UI |
| `chart.tsx` | tooltip numbers in the app language; colour variables as style text | locale-correct numbers; no `dangerouslySetInnerHTML` |
| `table.tsx` | `TableHead` and `TableCell` without `whitespace-nowrap` | long German labels, reasons and progress lines wrap inside the card instead of forcing a horizontal scroll; one-line columns say `whitespace-nowrap` |
| `spinner.tsx` | Restow's own; `label` prop, "Loading" for screen readers without one | small inline waits (page content uses skeletons) |

## Colour tokens

`src/index.css` defines the tokens for light and dark. Besides the zinc base:

- **Status tones** `success`, `warning`, `destructive`, `info`: `--<tone>` for fills,
  icons and tints, `--<tone>-foreground` for text on a solid fill, and
  `--<tone>-text` for text on the tone's tint (`bg-<tone>/10` to `/20`).
- **Chart palette** `--chart-1` to `--chart-5`: categorical, assigned in order.
- **Status chart palette** `--chart-success`, `--chart-warning`, `--chart-destructive`,
  `--chart-muted`: for status-coded series (backup and restore outcomes, recovery
  readiness). Charts take them from `STATUS_CHART_COLOR` in `components/kit`, so a
  state has the same colour on every page and matches its status badge. The UI tones
  (`--warning` and the rest) are for icons and tints and are too light for a bar.

The theme module puts `.light` or `.dark` on `<html>` before React renders. For the
one paint the browser may make before the bundle runs, `<html>` has neither class
and `src/index.css` gives the empty page the dark surface when the system prefers
dark.

`tokens.test.ts` enforces the contract in both themes: status text at least 4.5:1 on
every tint badge and alert use (it reads the alphas from their sources), chart slots and
status chart tokens at least 3:1 against `--card` and pairwise distinguishable for
normal and colour-blind vision, every chart config colour taken from one of the two
chart palettes, the pre-theme page surface equal to the dark tokens, and no raw hex
colours in this folder.

## Motion

Overlays that slide or zoom in (`dialog`, `alert-dialog`, `sheet`) and the `sidebar`
collapsing to its icon rail animate for 200 ms; small popups (`popover`, `tooltip`,
`dropdown-menu`, `hover-card`, `select`) use the 150 ms default of tw-animate-css.
The one exception is `drawer`: vaul
moves it with its own 500 ms transform transition, set inline while it follows a drag
gesture, which the class list cannot shorten.

## Layout contract of the registry primitives

The registry primitives lay out differently from the hand-written ones they replaced.
Existing screens were adjusted where they relied on the old behaviour; new code should
follow the registry contract below instead of re-creating the old one.

| Primitive | Registry contract | Keep in mind |
| --- | --- | --- |
| `Card` | the card owns the spacing: `flex flex-col gap-6 py-6`; sections only pad sideways (`px-6`) | tighten a card with `gap-*` on the card, not `pb-*` on the header; a card around a flush table or custom body takes `py-0` (or `pb-0` below a header) instead of zeroing the content padding |
| `CardHeader` | a grid with an optional `CardAction` slot top right | put a header action in `CardAction`; a header laid out by hand needs `flex` next to `flex-row` |
| `CardFooter` | `[.border-t]:pt-6` | a footer with `border-t` overrides the top padding with `[.border-t]:pt-*` (a plain `pt-*` loses on specificity) |
| `SelectTrigger` | `w-fit`; height from `size` (`default`, `sm`) | form selects take `w-full`; use `size="sm"`, not `h-8` |
| `SelectContent` | `position` defaults to `item-aligned`: the list opens over the trigger with the selected item in place | pass `position="popper"` for a list that drops below the trigger |
| `DropdownMenuItem` | `variant="destructive"`; icons are muted unless they carry a `text-*` class | a destructive item uses the variant, not `text-destructive` classes (those leave its icon grey) |
| `ScrollArea` | the viewport fills the root (`size-full`) | cap the height on the viewport (`[&>[data-slot=scroll-area-viewport]]:max-h-*`) or give the root a fixed height; a `max-h-*` on the root alone never scrolls |
| `Tabs` | the root is `flex flex-col gap-2`; `TabsContent` has no margin | add at most `mt-2` to reach 16 px under the list; `TabsList` height is set through the orientation group (`group-data-[orientation=horizontal]/tabs:h-auto` for a wrapping list) |
| `SheetContent` | `flex flex-col gap-4` | content with its own padding and spacing sets `gap-0` |
| `SheetHeader`, `SheetTitle` | header `p-4`; title at body size | inside a padded sheet the header takes `p-0`; a sheet title that should read as a heading takes `text-lg` |
| `Separator` | size from `data-[orientation=*]` | size a vertical separator with `data-[orientation=vertical]:h-*` |
| `Label` | `flex items-center gap-2` | wrap inline rich text in one element |
| `Table` | the container scrolls sideways (`overflow-x-auto`); heads in `text-foreground` | Restow cells wrap (see above); a column that must stay on one line says `whitespace-nowrap` |
| `Badge` | `w-fit shrink-0`; `white-space` inherited from the context (Restow, see above) | a long label wraps inside a narrow container; a column that must stay on one line says `whitespace-nowrap` and gives the badge room |

Screens built before this contract were adjusted with the smallest possible edit
(`flex` on hand-laid headers, `gap-*`/`py-0` on cards, `w-full` on form selects, `p-0`
on headers inside padded sheets, `variant="destructive"` on menu items). They still use
their own page headers, tables and empty states; moving them onto the full kit
(`CardAction`, data tables, alert dialogs for destructive actions) is separate work per
feature.
